# Multi-Agent Template

Шаблон рабочего пространства, в котором команда AI-агентов (на базе Claude Code) автономно выполняет задачи по разработке программного продукта — от планирования до деплоя — с минимальным участием человека.

## Основная идея

Один человек (основатель / CEO) ставит задачи. Всё остальное делает команда AI-агентов, каждый из которых играет конкретную роль: продакт-менеджер, архитектор, разработчик, ревьюер, девопс, дизайнер, технический писатель и т.д.

Центральное звено — **Оркестратор**: автономный агент, который получает задачу, разбивает её на шаги, подбирает нужные роли, запускает пайплайн, валидирует результат на каждом этапе и доводит до готового PR. Человек подключается только в точках эскалации — публичный контент, архитектурные решения с breaking changes, решения с затратами на инфраструктуру, или когда агенты не справились после нескольких попыток.

## Как это работает

Любая задача проходит через пайплайн из пяти шагов:

**PLAN → BUILD → TEST → VERIFY → SHIP**

Есть пять типов пайплайнов (feature, bugfix, infra, content, spike), и для каждого типа определены свои шаги, роли и гейты. Каждый шаг заканчивается валидацией: `APPROVED` — идём дальше, `NEEDS WORK` — агент исправляет. Если три попытки не помогли — подключается агент-помощник (helper). Если и он не справился — задача эскалируется на CEO.

Роли подбираются **динамически**: оркестратор анализирует сигналы задачи (файлы, ключевые слова, лейблы) и по индексу возможностей (`docs/role-capabilities.md`) выбирает Primary и Secondary роли. Если ни одна роль не подходит — создаётся ad-hoc роль на лету.

## Три режима работы

| Режим | Запуск | Что происходит |
|-------|--------|----------------|
| **CEO Mode** | `/orchestrator <задача>` | Человек даёт задачу, оркестратор выполняет |
| **Single Expert** | `/<роль> <вопрос>` | Прямой вызов конкретного эксперта, без пайплайна |
| **Autonomous** | `claude -p "/orchestrator ..."` | Оркестратор сам берёт задачи из бэклога и выполняет |

```
MyProject/
├── code/                  ← репозиторий продукта (изолирован через .gitignore)
├── docs/

│   ├── role-capabilities.md ← индекс возможностей ролей

```

## Ключевые принципы

- **Автономность**: агенты работают самостоятельно, CEO не участвует в операционке
- **Изоляция кода**: весь код модифицируется только через git worktree, основная директория — read-only
- **Динамический подбор ролей**: нет хардкода «эту задачу делает разработчик» — роли подбираются по сигналам
- **Многоуровневая валидация**: код-ревью, проверка безопасности, performance-бенчмарки
- **Граф знаний (AGE)**: модули, зависимости, security findings и code insights хранятся в графовой БД — агенты обогащают его по мере работы
- **Модели по уровням**: стратегические роли используют Opus, исполнительные — Sonnet, рутинные — Haiku

## Инфраструктура: AGE Graph + OpenBrain

Шаблон использует два ключевых инструмента для хранения знаний и координации между агентами.

### AGE Graph (Apache AGE + age-mcp)

Графовая база данных на PostgreSQL с расширением [Apache AGE](https://age.apache.org/), которая служит **базой знаний проекта**. Подключается к Claude Code как MCP-сервер ([age-mcp](https://github.com/Neftedollar/age-mcp) — F#/.NET, 21 tool).

Что хранится в графе: модули и их зависимости (`Module → DEPENDS_ON → Module`), пайплайны и шаги (`Pipeline → HAS_STEP → Step`), привязка ролей к шагам (`Step → PERFORMED_BY → Role`), связи между ролями (`Role → HELPS → Role`), а также `SecurityFinding` и `CodeInsight` — находки по безопасности и паттерны кода, которые агенты накапливают по мере работы.

Оркестратор использует граф на каждом шаге пайплайна: на этапе PLAN — чтобы понять scope и зависимости, на BUILD — чтобы передать разработчику контекст о ключевых классах и техдолге, на VERIFY — чтобы ревьюер видел известные уязвимости в затронутых файлах, на SHIP — чтобы определить целевой репозиторий.

После завершения задачи агенты **обновляют граф** — добавляют новые модули, security findings, code insights. Таким образом, база знаний растёт и обогащается с каждой итерацией.

Установка: `./tools/install-mcps.sh` — клонирует age-mcp, ставит dotnet global tool, поднимает PostgreSQL+AGE в Docker (порт 5435) и прописывает MCP-конфигурацию в Claude Code.

### OpenBrain

Оперативная память команды агентов — key-value хранилище с тегами. Используется для координации и отслеживания статуса.

Основные сценарии: блокировка задач (оптимистичный lock, чтобы два оркестратора не взяли одну задачу), тегирование прогресса (`code-done` → `pr-created` → `review-approved` → `completed-work` → `deploy-verified`), хранение результатов исследований (хук на WebSearch/WebFetch автоматически напоминает сохранять находки), и логирование создания ad-hoc ролей.

Также OpenBrain используется для crash recovery: записи `active-work` старше 24 часов автоматически помечаются как `stale-work`, и блокировка снимается.

## Хуки и автоматизация

Шаблон включает набор хуков Claude Code (`.claude/settings.json`), которые обеспечивают дисциплину без участия человека: блокировка опасных git-команд (`git push --force`, `reset --hard`), автолинтинг после каждого изменения файлов, проверка формата коммит-сообщений, логирование запуска субагентов, напоминание сохранять результаты исследований в OpenBrain, и проверка при завершении сессии — были ли запущены тесты и проставлены теги.

## Быстрый старт

```bash
# На чистой машине — всё в одну команду:
./bootstrap.sh MyProject my-github-org

# Или, если зависимости уже есть:
./setup.sh MyProject my-github-org

# Начать работу:
cd MyProject
claude
/orchestrator Реализовать авторизацию по OAuth2
```

## Для кого это

Для соло-разработчиков и небольших команд, которые хотят делегировать рутину AI-агентам и сфокусироваться на стратегических решениях. Шаблон превращает Claude Code из ассистента в полноценную автономную команду разработки с процессами, ролями и контролем качества.
